# StoQR Alert Email Setup

This guide documents the production mail path used for StoQR low-stock alert emails.

## Architecture

```text
StoQR alert trigger
  -> Supabase Edge Function: send-stoqr-alert-emails
  -> public SMTP submission endpoint
  -> Maddy on the Linux server
  -> ISP/provider SMTP relay
  -> recipient mailbox
```

The Edge Function submits alerts to Maddy using authenticated SMTP over implicit TLS. Maddy then relays outbound mail through a smarthost because Gmail rejects direct delivery from the home lab public IP.

## Public Network

Forward the public SMTP submission port to Maddy's implicit TLS submission port:

```text
120.88.173.186:16383 -> 192.168.1.6:465
```

Verify from outside or from a machine that can reach the public IP:

```bash
openssl s_client -connect 120.88.173.186:16383 -servername mail.rcsn01.com -brief
```

Expected result:

```text
Peer certificate: CN=mail.rcsn01.com
Verification: OK
```

## DNS

In Cloudflare, keep mail DNS records set to DNS-only, not proxied.

Minimum records:

```text
mail.rcsn01.com. A   120.88.173.186
rcsn01.com.      MX  10 mail.rcsn01.com.
rcsn01.com.      TXT v=spf1 ip4:120.88.173.186 mx -all
_dmarc.rcsn01.com. TXT v=DMARC1; p=none; rua=mailto:postmaster@rcsn01.com
```

Publish the DKIM TXT record generated by Maddy if sending directly. If using a smarthost, follow that provider's SPF/DKIM requirements too.

## Cloudflare API Token for Let's Encrypt

Create a Cloudflare API token scoped to the `rcsn01.com` zone.

Required permissions:

```text
Zone - Zone - Read
Zone - DNS - Edit
```

Zone resources:

```text
Include - Specific zone - rcsn01.com
```

Save it on the Linux server:

```bash
sudo mkdir -p /root/.secrets
sudo nano /root/.secrets/cloudflare.ini
sudo chmod 600 /root/.secrets/cloudflare.ini
```

File content:

```ini
dns_cloudflare_api_token = YOUR_CLOUDFLARE_TOKEN
```

Test the token:

```bash
TOKEN="YOUR_CLOUDFLARE_TOKEN"
curl -s "https://api.cloudflare.com/client/v4/zones?name=rcsn01.com" \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json"
```

The `result` array must include the `rcsn01.com` zone.

## Issue the TLS Certificate

Install Certbot and the Cloudflare DNS plugin on the Linux server:

```bash
sudo apt update
sudo apt install certbot python3-certbot-dns-cloudflare
```

Issue the certificate:

```bash
sudo certbot certonly \
  --dns-cloudflare \
  --dns-cloudflare-credentials /root/.secrets/cloudflare.ini \
  -d mail.rcsn01.com
```

The certificate should land at:

```text
/etc/letsencrypt/live/mail.rcsn01.com/fullchain.pem
/etc/letsencrypt/live/mail.rcsn01.com/privkey.pem
```

## Maddy Docker Config

Copy the sample env file and fill in relay credentials:

```bash
cd /srv/opense/mail
cp .env.example .env
nano .env
```

Required values:

```env
MADDY_HOSTNAME=mail.rcsn01.com
MADDY_DOMAIN=rcsn01.com
MADDY_TLS_CERT_FILE=/etc/letsencrypt/live/mail.rcsn01.com/fullchain.pem
MADDY_TLS_KEY_FILE=/etc/letsencrypt/live/mail.rcsn01.com/privkey.pem
MADDY_RELAY_HOST=mail.tpg.com.au
MADDY_RELAY_PORT=465
MADDY_RELAY_USERNAME=your-tpg-mailbox@tpg.com.au
MADDY_RELAY_PASSWORD=your-tpg-mailbox-password
```

The compose file mounts `/etc/letsencrypt` read-only into the container. Start Maddy:

```bash
docker compose up -d
docker compose logs --tail=80
```

Expected startup:

```text
submission: listening on tls://0.0.0.0:465
submission: listening on tcp://0.0.0.0:587
```

Create the SMTP submission user used by StoQR:

```bash
docker exec opense-maddy maddy creds create --password 'GENERATED_PASSWORD' alerts@rcsn01.com \
  || docker exec opense-maddy maddy creds password --password 'GENERATED_PASSWORD' alerts@rcsn01.com
```

Create a local mailbox for bounces if needed:

```bash
docker exec opense-maddy maddy creds create postmaster@rcsn01.com
```

## Supabase Edge Function Secrets

Set these secrets for the hosted Supabase project:

```bash
npx supabase secrets set --project-ref sllrsicziiasebqhytfr \
  ALERT_SMTP_USER=alerts@rcsn01.com \
  ALERT_SMTP_PASS='GENERATED_PASSWORD' \
  ALERT_MAIL_FROM='StoQR Alerts <alerts@rcsn01.com>' \
  ALERT_SMTP_PUBLIC_HOST=120.88.173.186 \
  ALERT_SMTP_PUBLIC_PORT=16383 \
  ALERT_SMTP_PUBLIC_SECURE=true \
  ALERT_SMTP_TLS_REJECT_UNAUTHORIZED=true \
  ALERT_SMTP_TLS_SERVERNAME=mail.rcsn01.com \
  ALERT_SMTP_IGNORE_TLS=false \
  ALERT_SMTP_REQUIRE_TLS=false \
  STOQR_ALERT_DISPATCH_TOKEN='change-me-too' \
  ALERT_EMAIL_DISPATCH_TOKEN='change-me-too'
```

Deploy the function:

```bash
npx supabase functions deploy send-stoqr-alert-emails --project-ref sllrsicziiasebqhytfr
npx supabase functions deploy send-stoqr-alert-notifications --project-ref sllrsicziiasebqhytfr
npx supabase functions deploy manage-stoqr-alert-connectors --project-ref sllrsicziiasebqhytfr
```

For automatic low-stock dispatch, configure the database to call the generic notification function:

```sql
INSERT INTO stoqr.alert_dispatch_config (singleton, function_url, dispatch_token)
VALUES (
  true,
  'https://sllrsicziiasebqhytfr.functions.supabase.co/send-stoqr-alert-notifications',
  'change-me-too'
)
ON CONFLICT (singleton) DO UPDATE
SET function_url = EXCLUDED.function_url,
    dispatch_token = EXCLUDED.dispatch_token,
    updated_at = timezone('utc'::text, now());
```

The repo root `./setup.sh` helper can perform the reset, deploy the alert functions, set both dispatch-token secret names, and reinsert this config row automatically.

## Verification

Check the public TLS endpoint:

```bash
openssl s_client -connect 120.88.173.186:16383 -servername mail.rcsn01.com -brief
```

Trigger an alert from StoQR or invoke the Edge Function with an authenticated user. The function should return:

```json
{"claimed":1,"sent":1,"failed":0}
```

Check delivery state:

```sql
select id, recipient, status, error_message, provider_message_id, sent_at
from stoqr.alert_delivery_logs
order by sent_at desc nulls last
limit 10;
```

Check Maddy:

```bash
docker compose logs --tail=100
```

## Troubleshooting

`write UNKNOWN | code=ESOCKET | command=CONN`

The Edge Function is likely trying STARTTLS against the forwarded port. Forward the public port to Maddy `465` and set:

```env
ALERT_SMTP_PUBLIC_SECURE=true
```

`invalid peer certificate: UnknownIssuer`

Maddy is presenting a self-signed cert. Use the Let's Encrypt setup above.

`invalid peer certificate: NotValidForName`

The certificate does not contain `mail.rcsn01.com`. Reissue the cert for `mail.rcsn01.com` and verify the public endpoint with `openssl`.

`Invalid login: 454 auth: invalid credentials`

The StoQR SMTP submission password does not match the Maddy `alerts@rcsn01.com` credential. Reset the Maddy credential and update `ALERT_SMTP_PASS`.

`550 The IP you're using to send mail is not authorized`

Gmail rejected direct-to-MX delivery from the home lab IP. Configure the Maddy smarthost relay.

`550 Policy-MFRM53 Relay Denied - Unauthorized`

TPG's relay is reachable but unauthenticated or unauthorized. Configure `MADDY_RELAY_USERNAME` and `MADDY_RELAY_PASSWORD`.

`535 Incorrect authentication data`

TPG rejected the relay credentials. Use the full TPG mailbox address and mailbox password, for example `user@tpg.com.au`, not necessarily the broadband customer number or portal password.
